# 出ていない記事の共通点を探した（2026-09-26）

**問い**: sitemap 92URL のうち索引に出ているのは一部だけ。**出ていないほうに共通点はあるか。**

測り方は `index-measure.md`。URL 一覧は `index-log/YYYY-MM-DD_ddg.txt` に保存する。
突き合わせは `python index_gap.py notes/index-log/<日付>_ddg.txt` で再現できる。

## 本日の実測

| | 値 |
|---|---|
| sitemap | **92 URL**（前回 09-25 と同じ） |
| DuckDuckGo（40ページ走査・`stopped:"cap"`・**下限**） | **45 URL**（09-25 は 40） |
| うち記事 | **43 / 88本**。出ていない記事 **45本** |

⚠ **これは Google の数字ではない。** Google は本日も測っていない（`site:` は bot 判定・CAPTCHA は解かない）。

## 答え — 共通点は1つだけ見つかった。「記事の作り」ではなく「追加された時期」

| 軸 | 出ている率 | 判定 |
|---|---|---|
| **追加時期** 早期（〜08/05） | **24/32 = 75%** | ✅ **これだけが分ける** |
| **追加時期** 後期（08/06〜） | **19/56 = 33%** | 〃 |
| カテゴリ「規格辞典」 | 27/67 = 40% | ❌ 期間で説明が付く（下記） |
| カテゴリ その他3種 | 16/21 = 76% | 〃 |
| 文字数 | 出 中央値 5,013字 / 未 6,111字 | ❌ 単調でない（7,500〜8,999字が85%で最高） |
| 記事からの被リンク数 | 出 中央値14 / 未 15 | ❌ **差が無い** |

### カテゴリ差は、期間を固定すると消える

| | 規格辞典 | その他 |
|---|---|---|
| 早期（〜08/05） | 10/14 = **71%** | 14/18 = **77%** |
| 後期（08/06〜） | 17/53 = **32%** | 2/3 = 66% |

**同じ期間なら、規格辞典もそれ以外も同じくらい出ている。**
規格辞典が低く見えたのは、**67本中53本が後期に追加されたから**である。
文字数・被リンク数も、後期の規格辞典 53本の中だけで比べると差が消える
（文字数 中央値 6,086 vs 6,424 / 被リンク 14 vs 13）。

## 技術側は本日も潰しておいた（原因ではない）

| 見たもの | 結果 |
|---|---|
| トップページからの内部リンク（本番HTML） | **92件**。全記事が1クリックで辿れる。取りこぼしは無い |
| sitemap の `lastmod` | **記事ごとに別の日付**（`build.py:494` が記事の `date` を使う）。「毎回全URLが今日更新」にはなっていない |
| `robots.txt` / `X-Robots-Tag` | Allow / noindex なし（09-25 実測のまま） |

## だから何が言えるか（ここを超えて書かない）

- **出ていない45本に、直せる共通の欠陥は見つからなかった。** 長さ・被リンク・カテゴリのどれでも分かれない
- 分かれたのは**時期だけ**。これは記事側で直せる属性ではない
- ⚠ **「時期が原因だ」とは書かない。** 時期と相関する未測定のものが他にある可能性を潰していない
- **1日で 40 → 45 に増えた。**「止まっている」ではなく**進んでいる**。ただし2点しか無く、増えた5件の内訳は
  09-25 に URL 一覧を保存していなかったため**特定できない**。本日から一覧を保存する（再発防止）

## 次に測ること

**同じ手順で数日測り、増えた分がどの時期の記事かを見る。**
後期の記事が順に増えるなら時間の問題であり、**記事側の改稿では動かせない**。
早期ばかりが増え直すなら、後期に何か別の原因がある。
⚠ **記事を増やしても、この問いの答えは出ない。**
