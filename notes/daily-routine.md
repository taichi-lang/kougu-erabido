## やること（1日分）

**方針: 新規記事は毎日3本＋過去記事1本の改修**（2026-09-29 決定。旧方針「1日0〜1本」から戻した）。
この方針は3か所に書かれている。**変えるときは3か所すべてを直す。**

| 場所 | 役割 |
| --- | --- |
| vault `20_Projects/工具えらび堂 事業方針.md` | 判断基準の本体 |
| `~/.claude/scheduled-tasks/b5-kougu-routine/SKILL.md` | 毎日走るルーティーン |
| このファイル | 実行手順（リポジトリ内で自己完結させた版） |

1. **新規記事を3本書く**
2. **過去記事を1本改修する**（下の改修キューの上から1本）
3. `python audit.py --gate` を通す（**終了コード0でないものは公開しない**）
4. `python build.py`
5. `notes/rewrite-log.md` に、改修した記事の行を1行足す
6. コミットする（Conventional Commits）

**デプロイと IndexNow 送信は太一の作業。** 自動実行ではコミットまでで止める。

## 「1本」の定義（満たさないものは1本と数えない）

| # | 条件 |
| --- | --- |
| 1 | **比較表（META の `products` 3件以上）が本文中にある。** `{{PRODUCT_TABLE}}` を本文の該当箇所に置く（記事末尾ではない） |
| 2 | **商品の仕様はメーカー公式の公表値のみ。** 小売店の記載を仕様として書かない。**公式で取れない項目は書かない**（「公式表記を確認できていないため記載しない」と明記する） |
| 3 | 価格は実売の調査値。`price_note` に調査時点を書く |
| 4 | **本文中の内部リンクを4本以上**（存在する slug に限る。`python linkcheck.py` で0件を確認） |
| 5 | 体験を装う表現を書かない（「使ってみた」等）。`shop_keyword` は記事のテーマまで絞る |

**販売店リンクは書かなくてよい。** `links` が空なら「メーカー名 型番」での楽天/Amazon検索リンクが自動生成される。
